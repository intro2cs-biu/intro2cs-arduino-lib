The computing platform

Arduino as a programmable system

An Arduino Uno is a small computer designed to interact directly with electronic components. Unlike a desktop computer, it normally runs one compiled program repeatedly and has no operating system, keyboard, or screen of its own. The course kit supplies those interactions as separate components.

The board contains a processor, program memory, working memory, a USB connection, and electrical connection points called pins. Your C program configures each pin before using it. An input pin observes a voltage produced by a button or sensor. An output pin produces a voltage that controls an LED, buzzer, or display.

Digital pins use two logical states. LOW is approximately 0 volts and represents 0; HIGH is approximately 5 volts and represents 1. The voltage is the physical signal; LOW and HIGH are the names used by the program. Analog input pins measure a range of voltages and convert that measurement to an integer from 0 to 1023.

For convenience, each kit includes a breadboard for temporary electrical connections. In the central area, each numbered row is divided into two groups of five connected holes: A–E on one side of the center gap and F–J on the other. Holes within one five-hole group share the same electrical point; the center gap separates the two groups. Component legs that must remain electrically separate belong in different rows or on opposite sides of the gap. The long side rails are commonly used to distribute 5V and GND. A working circuit requires a complete electrical path through power, signal, and ground.

What is an Arduino pin?

The sockets marked 0–13 and A0–A5 are called pins. A wire connects a component to a pin. “Connect the button to pin 2” means the socket marked 2 on the Arduino.

Getting started

Build and run the first program

This walkthrough begins with a complete source file and takes it through compilation and upload. The program uses only function calls; control structures are introduced later in the course.

Important

Disconnect the USB cable before inserting or moving components.

Assemble the circuit

  1. Place the LED so its legs enter two different numbered breadboard rows on the same side of the center gap. Both legs must not share one connected five-hole row.
  2. In the LED’s long-leg row, connect one end of a 220–330 Ω resistor. Connect the resistor’s other end to Arduino pin 2.
  3. Connect the LED’s short-leg row to the breadboard GND rail, then connect that rail to Arduino GND.
  4. Connect the LCD directly to the Arduino, without the breadboard: GND→GND, VCC→5V, SDA→A4, and SCL→A5.
  5. Check each connection, then reconnect USB.
ex0-arduino.c 
#include "arduino.h"
#include "lcd.h"

int main(void)
{
    pinMode(2, OUTPUT);
    lcdBegin(16, 2);
    lcdPrintf("Hello, World!");
    digitalWrite(2, HIGH);
}

Create and run the file

  1. Download intro2cs-arduino-lib.zip and extract it. Keep the extracted folder name intro2cs-arduino-lib.
  2. Open a plain-text editor and create a new file named ex0-arduino.c. The .c extension identifies it as C source code.
  3. Copy the complete program above into the file and save it beside the extracted intro2cs-arduino-lib folder.
  4. Open a terminal in that directory. Use pwd to confirm the current directory and ls to confirm that both the source file and library folder are present.
  5. Run the three commands in the next section: compile, create the HEX file, and upload.
  6. After upload, the LCD should show “Hello, World!” and the LED connected to pin 2 should turn on.

#include provides the declarations for a library module. arduino.h is required for basic pin functions and lcd.h for screen functions. pinMode configures pin 2 as an electrical output. lcdBegin initializes the LCD before it is used. The final two calls send characters to the screen and set pin 2 to HIGH.

Keeping an experiment alive

Some display features are refreshed in the background. During experiments, adding while (1) { } at the end of main keeps the program active. Remove it when an assignment requires the submitted function to finish.

From C file to Arduino

Compile and upload

Compilation translates the C source and library into an executable file. Conversion produces the HEX data that will be stored in the Arduino’s program memory. Uploading transfers that data over USB.

  1. Compile

    avr-gcc -mmcu=atmega328p -DF_CPU=16000000UL -Os -std=c99 \
  -Iintro2cs-arduino-lib/headers ex0-arduino.c \
  intro2cs-arduino-lib/libintro2cs-arduino.a -o ex0-arduino.elf

  2. Create the Arduino file

    avr-objcopy -O ihex -R .eeprom ex0-arduino.elf ex0-arduino.hex

  3. Identify the USB serial connection

    Use the instructions below for your operating system, then copy the complete connection name.

  4. Upload using your connection name

    avrdude -p atmega328p -c arduino -P /dev/cu.usbmodem2101 \
  -b 115200 -D -U flash:w:ex0-arduino.hex:i

macOS

Run ls /dev/cu.usb*. Copy the complete result, such as /dev/cu.usbmodem2101, and use it after -P.

Linux

Run ls /dev/ttyACM* /dev/ttyUSB*. Copy the device that appears when the Arduino is connected, commonly /dev/ttyACM0. Your user may need serial-port permission.

Windows

Open Device Manager → Ports (COM & LPT), connect the Arduino, and note the new entry such as COM4. In the upload command use -P COM4.

In every operating system, the value after -P identifies the USB serial connection. Copy the exact value shown by your computer; do not copy the example unchanged.

1 · Include arduino.h

Basic Arduino pins

To use this module, add #include "arduino.h". It exposes functions for configuring pins, sending and reading electrical signals, measuring analog voltages, delaying execution, and controlling a passive buzzer.

Before using a digital pin, configure its direction with pinMode. An output is driven by the Arduino, so the program chooses the voltage. An input is driven by the external circuit, so the program observes the voltage without forcing it.

OUTPUT

The Arduino sends a signal. Example: turn an LED on or off.

INPUT

The Arduino listens. The circuit must provide a clear HIGH or LOW signal.

INPUT_PULLUP

The Arduino listens and holds the pin HIGH internally. A button between the pin and GND reads HIGH when released and LOW when pressed.

Continuous input and output example

Connect a button between pin 2 and GND, a red LED with a resistor to pin 3, the RGB LED’s channels through separate resistors to pins 9, 10, and 11, and an active buzzer to pin 8 and GND. The loop repeatedly samples the button so the program remains responsive.

#include "arduino.h"

int main(void)
{
    pinMode(2, INPUT_PULLUP);
    pinMode(3, OUTPUT);
    pinMode(8, OUTPUT);

    while (1) {
        char pressed = digitalRead(2) == LOW;
        digitalWrite(3, pressed ? HIGH : LOW);
        digitalWrite(8, pressed ? HIGH : LOW);
        analogWrite(9, pressed ? 255 : 0);
        analogWrite(10, 0);
        analogWrite(11, pressed ? 0 : 255);
    }
}
FunctionWhat it doesReturns
pinMode(pin, mode)Configures the electrical role of an Arduino pin. OUTPUT allows the program to drive LOW or HIGH. INPUT lets an external circuit determine the voltage. INPUT_PULLUP is an input with an internal resistor that keeps it HIGH until a button connects it to GND.—
digitalWrite(pin, value)Sets a configured output to HIGH (approximately 5V) or LOW (approximately 0V). This is appropriate for on/off components such as an LED or active buzzer.—
digitalRead(pin)Samples the electrical state of a configured input at the instant of the call.HIGH or LOW
analogRead(pin)Measures the voltage on A0–A5 and converts the range from 0V to 5V into an integer scale.0–1023
analogWrite(pin, value)Produces a rapidly switched signal whose average power is controlled by a value from 0 to 255. On pins 3, 5, 6, 9, 10, and 11, the pin still switches only between 0V and 5V, but it does so rapidly. The value controls the percentage of time spent HIGH: 0 is always LOW, 255 is always HIGH, and 128 is HIGH approximately half the time. LEDs appear dimmer because the eye averages these fast pulses.—
delay(ms)Stops execution for the requested number of milliseconds. No later statement runs during the delay.—
delayMicroseconds(us)Stops execution for a much shorter interval measured in microseconds.—
tone(pin, frequency, duration)Alternates a passive-buzzer pin HIGH and LOW at the requested frequency, in hertz, for the requested positive duration in milliseconds. This implementation blocks until the note finishes.—
noTone(pin)Drives the selected buzzer pin LOW. Because tone is blocking, this is used after separate/manual buzzer control rather than to interrupt a running note.—

Configuration precedes use: call pinMode before reading from or writing to a basic pin.

2 · Include lcd.h

LCD text screen

The screen presents two rows of sixteen character cells. Internally it remembers both the characters and a cursor position—the location where the next write begins.

Text, cursor, and display state

lcdPrint writes a sequence of characters beginning at the cursor and advances the cursor after every character. It does not erase earlier content. lcdWrite performs the same operation for one character value.

lcdSetCursor(column, row) selects a location before writing. Coordinates begin at zero, so the upper-left cell is (0, 0) and the first cell of the second line is (0, 1). Clearing and scrolling are separate operations: clearing replaces cells with spaces, while scrolling shifts the visible window over the stored display contents.

The physical controller normally stores up to 40 character positions per row although only 16 are visible. lcdPrint has no software length check, but text beyond the controller memory wraps and may overwrite earlier positions. For predictable scrolling, keep a scrolling line to at most 40 characters. lcdPrintf additionally limits its formatted result to 63 characters.

#include "lcd.h"
int main(void)
{
    lcdBegin(16, 2);
    lcdSetCursor(0, 0);
    lcdPrint("Hello!");
    lcdSetCursor(0, 1);
    lcdPrintf("Score: %d", 42);
}
FunctionWhat it doesReturns
lcdBegin(cols, rows)Initializes communication with the screen, configures its dimensions, turns the display on, and clears its character memory. For the kit screen, pass 16, 2. Call it once before any other LCD operation.—
lcdPrint(text)Sends every character in a null-terminated C string to consecutive screen cells, starting at the current cursor. It advances the cursor but does not clear existing content first.—
lcdWrite(character)Sends one character code to the current cursor position. Use it for a single ordinary character or for a custom character created with lcdCreateChar.—
lcdPrintf(format,...)Formats integers, strings, and characters using familiar printf placeholders, then prints the result. The internal formatted text is limited to 63 characters.—
lcdSetCursor(col,row)Moves the insertion point without modifying displayed text. On the kit screen, columns are 0–15 and rows are 0–1.—
lcdClear() / lcdClearRow(row)Erases the entire display, or replaces every cell of one row with a space. Both operations leave the cursor at the beginning of the cleared area.—
lcdHome()Moves the cursor to the upper-left cell without erasing any characters.—
lcdScrollDisplayLeft/Right()Shifts the complete visible display by one character position. Repeated calls produce a scrolling effect.—
lcdCursor/NoCursor()Shows or hides the underline that marks the current cursor position.—
lcdBlink/NoBlink()Enables or disables blinking at the current cursor position.—
lcdDisplay/NoDisplay()Turns the visible characters on or off without erasing the stored text. Calling lcdDisplay restores it.—
lcdLeftToRight/RightToLeft()Selects the direction in which the cursor moves after a character is written.—
lcdAutoscroll/NoAutoscroll()Controls whether the display automatically shifts when a new character is written.—
lcdCreateChar(place,drawing)Stores an eight-row, five-pixel-wide bitmap in one of eight custom-character positions, numbered 0–7.—
lcdBacklight/NoBacklight()Turns the screen’s background illumination on or off; stored characters are not changed.—

3 · Include keypad.h

Four-by-four keypad

A keypad is an array of switches at the intersections of four row wires and four column wires. The library scans those intersections and converts the pressed position to an integer from 0 through 15.

Default wiring and values

Number the keypad connector positions from 1 through 8 in the orientation shown. Connect keypad position 1 to Arduino pin 1, position 2 to pin 2, and continue directly through position 8 to pin 8. The first four carry rows and the final four carry columns. Printed symbols vary between keypads, so the API uses position-based values:

0123456789101112131415
#include "keypad.h"
int main(void)
{
    keypadBegin(NULL, NULL);
    int key = keypadGetKey();
}
FunctionWhat it doesReturns
keypadBegin(rows,cols)Initializes the eight keypad connections and prepares the library to scan the sixteen button positions. Pass NULL, NULL to select the default 1-to-1 through 8-to-8 wiring. Call once before reading keys.—
keypadGetKey()Scans each row until it detects a closed row-column switch. The function waits while no key is pressed, then waits again until the selected key is released so one physical press produces one result.The position value 0–15

4 · Include matrix.h

8×8 LED dot matrix

The matrix contains 64 LEDs, but only sixteen external legs: eight select rows and eight select columns. The library activates rows rapidly in sequence, producing the appearance of one stable image.

Wiring rule

Connect matrix leg 1 to Arduino pin 1, leg 2 to pin 2, and continue through leg 16 to Arduino pin 16 (also marked A2). The physical leg number and Arduino pin number remain identical throughout.

To identify the legs, hold the matrix with its printed model code facing you. The pins on the front-facing side are read left to right according to the component numbering; after turning the component around, the visible order is reversed. Check the package notch or supplied pin figure before inserting it, because rotating the matrix changes which physical leg enters each breadboard row.

#include "matrix.h"
int main(void)
{
    unsigned char picture[8] = {
        0b00111100, 0b01000010, 0b10100101, 0b10000001,
        0b10100101, 0b10011001, 0b01000010, 0b00111100
    };
    matrixBegin(NULL, NULL);
    matrixSet(picture);
}

The same picture can be passed as one 64-bit value with matrixSet64(UINT64_C(0x3C42A581A599423C));. Use uint64_t, not int: on the Uno, int is only 2 bytes, while a complete matrix requires 8 bytes.

The array holds one eight-bit pattern for each physical row. A 1 lights a dot and a 0 leaves it dark. Within each pattern, the leftmost binary digit controls the leftmost matrix column.

matrixSet(picture)Copies eight packed row patterns into the matrix’s internal image. The background refresh immediately begins displaying the new contents.—
matrixSet64(frame)Accepts one uint64_t containing all 64 pixel bits. The most significant eight bits describe the top row; the least significant eight bits describe the bottom row. Within every row, the most significant bit is the leftmost pixel.—
matrixSet2D(picture)Converts an 8×8 C array into packed row patterns. Every nonzero array element becomes a lit dot.—
matrixSetRow(row,values)Replaces one row, numbered 0–7, using an array of eight values. Nonzero values light their corresponding columns.—
matrixSetRowByte(row,pattern)Replaces one row with a compact eight-bit pattern; bit 7 is the leftmost column.—
matrixSetPixel(row,col,value)Changes one dot without altering the other 63. Rows and columns are numbered 0–7; zero turns the dot off and nonzero turns it on.—
matrixClear()Sets every stored row pattern to zero. Automatic refresh continues, but all dots are dark.—
matrixStop()Stops automatic refresh and electrically disables all rows and columns. Call matrixBegin again before displaying another image.—

5 · Include digits.h

Seven-segment displays

Each digit is constructed from seven independently controlled bars and an optional decimal point. The one-digit display controls one set directly; the four-digit display shares the segment connections and selects its positions rapidly in sequence.

ABCDEFGDP

How a pattern describes one digit

The API represents the on/off state of all eight lights as the eight binary digits of one unsigned char. From right to left, its bits control A, B, C, D, E, F, G, and DP.

bit:       7  6  5  4  3  2  1  0
segment:   DP G  F  E  D  C  B  A
zero:      0  0  1  1  1  1  1  1
C value:   0b00111111

Zero lights A–F, but not G or DP.

Always begin first

Use digitsBegin(NULL, NULL, 1) for one digit, or digitsBegin(NULL, NULL, 4) for four.

#include "digits.h"
int main(void)
{
    digitsBegin(NULL, NULL, 1);
    digitsSetSegments(0b00111111, 0b0001); /* show 0 */
}
FunctionWhat it doesReturns
digitsBegin(segmentPins,digitPins,count)Stores the wiring, configures the segment and digit-selection pins, clears the display, and starts automatic refresh. Pass NULL arrays for default wiring and choose a count from 1 through 4. Call once before setting segments.—
digitsSetSegments(pattern,positions)Copies the same eight-bit segment pattern to each selected position. The positions argument is also a bit pattern: bit 0 selects the rightmost digit, bit 1 the next digit, and so on.—
digitsSetDisplay(display)Updates all digit positions from one 32-bit value containing four consecutive eight-bit segment patterns. The least significant eight bits describe the rightmost position.—
digitsSetSegment(digit,segment,value)Changes one bar without replacing the rest of the display. Digit 0 is rightmost; segments 0–7 mean A, B, C, D, E, F, G, DP. HIGH turns the selected segment on.—
digitsClear()Clears every stored segment pattern. Refresh continues with all segments off.—

Directions reversed?

The direction helpers assume the component labels face the user and the connector edge points away from the user. In that orientation, pushing the stick toward the printed left, right, up, or down side activates the matching helper. If your module is mounted differently, rotate it or exchange the direction used in the program.

When combining components

Pin and feature compatibility

Most beginners can skip this until using several components together.

The processor contains three hardware timers: circuits that count clock pulses independently of the main program. The library uses Timer0 to switch rapidly between the positions of the four-digit display and Timer1 to scan the rows of the LED matrix. analogWrite also relies on these timers for particular pins. Two features that reconfigure the same timer cannot reliably operate together. Assigning display refresh to a different timer would not remove this limitation; it would make a different pair of analogWrite pins unavailable.

Avoid these combinations:
  • After digitsBegin, do not use analogWrite on pins 5 or 6.
  • After matrixBegin, do not use analogWrite on pins 9 or 10.
  • Do not connect two components to the same Arduino pin.

The buzzer does not reserve a timer; the program simply waits while a note plays.

Something did not work?

Troubleshooting

My program cannot find a header

Include the matching file: arduino.h, lcd.h, keypad.h, matrix.h, digits.h, or joystick.h. Keep the compile command’s -Iintro2cs-arduino-lib/headers.

A component does nothing

Unplug USB, check every wire, and ensure the component’s Begin function is called first.

The LCD lights but shows no text

Check four wires, adjust the small contrast control, and call lcdBegin(16, 2) before printing.

Upload cannot find the Arduino

Reconnect USB, run ls /dev/cu.usb*, and copy its result after -P.
